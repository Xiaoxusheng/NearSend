# 安全说明

本文说明本服务的安全模型、已实现的控制、以及**明确不具备**的能力。
最后一节是使用前必读的使用边界。

---

## 1. 威胁模型

服务运行在一个**局域网**中。假设：

- 局域网内的设备**部分可信**：你自己家庭的网络里，其它设备基本是你自己的；
  但办公室、宿舍、共享 Wi-Fi 里可能出现陌生设备。
- 服务使用**明文 HTTP**，链路上的其它设备可以嗅探流量。
- 任何设备都可以访问 `GET /api/health`、`POST /api/session`，从而获得一个会话。
  **获得会话 ≠ 获得权限**，权限模型见下。

防护目标：

| 目标 | 实现 |
| --- | --- |
| 陌生设备不能读取别人的文件 | 任务参与者校验 + 下载票据 |
| 陌生设备不能修改服务配置 | 特权分离 + 管理令牌 |
| 陌生设备不能向任意目录写文件 | 路径净化 + 受控根目录 + 原子提交 |
| 恶意文件名不能导致目录逃逸 | `SanitizeName` / `SanitizeRelPath` / `SafeJoin` |
| 大请求 / 非法参数不能打垮服务 | 请求体上限 + 索引与长度校验 + panic 兜底 |
| 不泄露内部信息 | 统一错误结构 + 日志与响应分离 |

**不防护**：链路上的窃听与中间人（没有 TLS）。见第 5 节。

## 2. 鉴权与授权

### 2.1 会话

```
POST /api/session  →  { device: {id, name, ...}, token: "<64 位十六进制>" }
```

- 设备 ID 与令牌都由服务端用 `crypto/rand` 生成（32 字节），**客户端无法指定**。
- 令牌持久化在 SQLite 中，因此刷新页面不会掉线，也不会被强制重新配对。
- 校验方式：`Authorization: Bearer <token>`（HTTP）或首帧 `client.hello`（WebSocket）。

**同名设备拥有不同的会话标识**，设备名称只用于展示，**从不作为身份凭据**。

### 2.2 授权矩阵

| 操作 | 发送方 | 接收方 | 第三方 | 特权设备 |
| --- | --- | --- | --- | --- |
| 查看任务详情 | ✅ | ✅ | ❌ 403 | ✅ |
| 上传分块 | ✅ | ❌ 403 | ❌ 403 | ❌ 403 |
| 接受 / 拒绝 | ❌ 403 | ✅ | ❌ 403 | ❌ 403 |
| 下载（签发票据） | ❌ 403 | ✅ | ❌ 403 | ✅ |
| 取消 | ✅ | ✅ | ❌ 403 | — |
| 暂停 / 继续 / 重试 | ✅ | ✅（暂停） | ❌ 403 | — |
| 查看分块状态 | ✅ | ✅ | ❌ 403 | — |
| 修改设置 / 信任管理 / 清历史 / 清临时文件 | — | — | ❌ 403 | ✅ |

判定顺序固定为 **鉴权 → 参与者 → 状态 → 参数**。顺序很重要：
先查状态再查参与者，会让第三方通过错误码差异探测到任务是否存在。

### 2.3 特权来源

特权只来自两条，**都不能由客户端自行声称**：

1. **请求来自主机回环地址**（`127.0.0.1` / `::1`）——部署者本人就在这台机器上；
2. **该设备已被授予信任**——由特权设备在设备管理页授权，或凭管理令牌一次性认领。

管理令牌（`admin-token.txt`，权限 0600）在首次启动时生成并打印到控制台，
用于「服务跑在无头机器上，只能从另一台电脑配置」的场景。

> 本项目**刻意不提供**「系统中没有受信任设备时自动放行」的兜底。
> 在共享局域网里，那等于让任意陌生人取得管理权限。

撤销信任会**立即断开**该设备的实时连接——信任不是前端标记，而是连接资格。

### 2.4 下载票据

浏览器触发原生下载（`<a download>`）时无法携带自定义请求头。
把会话令牌放进 URL 会进入访问日志与浏览器历史，因此使用票据：

- 短期有效（120 秒）；
- 绑定 `taskId + fileIndex + deviceId`；
- 单一用途：**只能用于下载那一个文件**，不能调用任何其它接口；
- 即使被记录，也无法用于其它任务或接口。

票据过期或被撤销后返回 `forbidden`。

## 3. 文件系统安全

### 3.1 文件名净化

`fsutil.SanitizeName` 依次处理：

1. 统一 `\` 为 `/`，只取最后一段（阻止 `a/b` 形式的注入）；
2. 去首尾空白；
3. 替换非法字符 `\ / : * ? " < > |` 与控制字符为 `_`；
4. 去掉首尾的 `.` 与空格（阻止 `..` 与 `... `）；
5. 超长按 **UTF-8 字节**截断并保留扩展名（Linux 限制 255 字节，纯中文占 3 字节/字）；
6. Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9`）加前缀。

空结果或全非法字符返回 `ErrEmptyName`。

`SanitizeRelPath` 逐段净化并**丢弃空段与 `..`**，因此结果不可能包含上级引用。

### 3.2 路径约束

`fsutil.SafeJoin(root, parts...)`：

1. `filepath.Join` 后取绝对路径，比较是否在 `root` 之下（Windows 忽略大小写）；
2. 向上找到最近的**已存在祖先**并 `EvalSymlinks`，再拼回剩余片段，比较是否仍在 `root` 内。

第 2 步是为了阻止**符号链接逃逸**：只比较字符串前缀无法发现
`root/link → /etc` 这种把目标引到根目录外的软链接。

### 3.3 写入流程

```
分块 → 临时文件（受控的 tempDir/transfers/<taskId>/）
     → 逐步校验（每块 SHA-256，整文件 SHA-256）
     → 原子提交（同目录 rename；跨卷退化为复制+fsync+删除）
     → 最终文件（受控的 receiveDir/<日期>/<发送方>/）
```

- **校验不通过的字节永不落入临时文件**（先算哈希再写）。
- **目标为目录时提交一律失败**，不会试图覆盖目录。
- 默认策略 `rename`，`neverOverwrite` 兜底确保「绝不静默覆盖」。

### 3.4 清理边界

| 目录 | 清理规则 |
| --- | --- |
| `<tempDir>/transfers/*` | 按状态与保留期清理；进行中的任务永不触碰 |
| `<receiveDir>/**` | **从不自动删除**。只有用户手动清理磁盘 |

「清除历史记录」只把记录标记为不可见（`history_visible = 0`），**不删除任何文件**。
界面的确认弹窗里也明确写出这一点。

## 4. Web 层防护

| 项 | 措施 |
| --- | --- |
| 请求体大小 | JSON 接口 2 MiB；分块接口 `chunkSize + 4 KiB`（`http.MaxBytesReader`） |
| 未知字段 | `DisallowUnknownFields`，拒绝尾随内容 |
| 参数校验 | 分块索引范围、期望长度、文件索引存在性、状态合法性 |
| 路径遍历 | 见第 3 节 |
| panic | 顶层 `recover`，返回 `internal` 错误码，进程不退出 |
| 静态资源 | 只服务 `publicDir` 之下；未知 `/api/*` 返回 404 而非首页 HTML |
| 响应头 | `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: SAMEORIGIN` |
| CSP | `default-src 'self'`；`worker-src 'self' blob:`（哈希 Worker 需要）；`object-src 'none'`；`frame-ancestors 'self'` |
| WebSocket Origin | 比对 Host，不使用通配 |
| 令牌进 URL | 禁止；WebSocket 用首帧握手，下载用短期票据 |
| 日志 | 不记录完整令牌；只记录设备 ID 与来源 IP |
| 错误响应 | 只有稳定错误码 + 面向用户的中文文案；绝对路径/堆栈只写服务端日志 |

### 跨站请求

所有状态变更接口都要求 `Authorization` 头，浏览器不会在跨站请求中自动携带它，
因此天然免疫基于 Cookie 的 CSRF。CSP 的 `connect-src 'self'` 进一步限制了
页面能发起的连接目标。

## 5. 加密边界（必读）

### 事实

本服务通过**明文 HTTP** 提供局域网访问，**没有启用 TLS**。

因此：

- 传输内容（含文件名）对同一网络中的其它设备是**可嗅探的**；
- 不具备**端到端加密**能力；
- 不具备**前向保密**；
- 无法防御局域网内的**中间人**攻击。

### 本项目不做的事

- 不声称任何未实现的加密能力；
- 不使用「局域网很安全」作为省略 TLS 的理由；
- 诊断页与设置页都会显示这条提示，而不是把它藏在文档里。

### 使用建议

| 场景 | 建议 |
| --- | --- |
| 家庭网络 / 自己手机热点 | 可以使用 |
| 公司内网（有网络管理员） | 谨慎：可被嗅探，不建议传敏感文件 |
| 咖啡馆 / 机场 / 酒店 Wi-Fi | **不要使用** |
| 必须跨不可信网络 | 前置 TLS 反向代理（Caddy / Nginx + 证书），或改用 VPN |

### 关于 `crypto.subtle`

Web Crypto 只在**安全上下文**（HTTPS 或 localhost）可用。
局域网访问通常是 `http://192.168.x.x`，属于非安全上下文，`crypto.subtle` 为 `undefined`。

如果只依赖它，**分块哈希校验会在真实部署场景静默失效**。
因此前端实现了三级降级：

1. Web Crypto（安全上下文）→ 硬件加速；
2. Web Worker 池 + 纯 JS SHA-256（明文 HTTP 的常规情况）→ 多核并行且不阻塞界面；
3. 主线程纯 JS（Worker 被 CSP 拦截时）→ 分片计算并让出主线程。

诊断页会**如实显示当前实际使用的实现**，并用公开测试向量做自检。

## 6. 拒绝服务与资源限制

| 资源 | 限制 |
| --- | --- |
| 并发传输任务 | `maxConcurrentTransfers`（默认 3），超出排队 |
| 单文件大小 | `maxFileSize`（默认 32 GiB），创建时即拒绝 |
| 单任务总大小 | `maxTaskSize`（默认 64 GiB），创建时即拒绝 |
| 单块大小 | 服务端按 `chunkSize` 精确校验，多 1 字节也拒绝 |
| 带宽 | `bandwidthLimit`（默认不限），令牌桶限速 |
| WebSocket 发送队列 | 64 条，溢出即断开慢客户端 |
| WebSocket 消息 | 8 KiB 上限 |
| JSON 请求体 | 2 MiB 上限 |
| HTTP 头 | 64 KiB 上限 |
| 僵死任务 | `updated_at` 超过 10 分钟无进展即回收并释放槽位 |
| 内存 | 分块按单块读入（上限 64 MiB）；整文件哈希与下载全程流式 |

单个请求出错不会拖垮服务：顶层 `recover` 会记录日志并返回 `internal`。

## 7. 临时接收箱的安全语义

临时入口**免确认**接收，看起来像「无鉴权的上传接口」。它的实际约束：

| 约束 | 实现位置 |
| --- | --- |
| 令牌 128 位随机 | `newToken()`（32 字节 hex） |
| 绝对过期时间 | `dropboxes.expires_at`，后端每次请求都校验 |
| 手动关闭立即失效 | `DisableDropbox` 把 `expires_at` 设为当前时间 |
| 重新签发使旧令牌失效 | `UpsertDropbox` 覆盖令牌 |
| 过期后后端拒绝一切请求 | `Create` 返回 `dropbox_expired`（HTTP 410） |
| 不绕过其它规则 | 接收目录、重名策略、大小限制全部照旧生效 |
| 真实统计 | `received_count` / `received_bytes` 来自真实收件 |

**它不是永久接口**：默认 30 分钟，最长 24 小时；页面上的倒计时过期后会向后端
再确认一次，以后端结论为准。

风险提示（界面中已写明）：有效期内任何拿到链接的人都能上传，请勿转发给不受信任的人。

## 8. 使用前自查清单

- [ ] 我是在**可信的局域网**中使用（自己的家庭网络或手机热点）吗？
- [ ] 我在传输敏感文件吗？如果是，请先了解明文 HTTP 的风险。
- [ ] 接收目录所在磁盘有足够空间吗？
- [ ] 开启临时入口后，我是否只把地址发给了该发的人？
- [ ] 借用他人设备传输后，是否需要撤销信任或移除该设备？

## 9. 报告安全问题

本项目为个人/内部使用项目，未指定安全响应流程。
如果在使用中发现安全问题，请附上复现步骤与影响范围记录在你的使用环境中，
并优先考虑降低暴露面（关闭临时入口、撤销信任、限制监听地址为 `127.0.0.1`）。
